# Livrer un résultat vérifié

Utiliser les points applicables au projet ; ce document n'impose pas la création de services ou d'infrastructure.

- [ ] Les critères utilisateurs sont reproduits sur le résultat intégré.
- [ ] Les tests applicatifs configurés réussissent ; les tests du template seuls ne suffisent pas.
- [ ] Les défauts de revue ont une disposition explicite et le SHA livré est identifiable.
- [ ] Le démarrage et la vérification sont reproductibles depuis le README.
- [ ] Les variables nécessaires sont documentées avec des exemples sans secrets.
- [ ] Les données de test et les préférences personnelles ne sont pas publiées.
- [ ] Les opérations de migration ont été éprouvées sur un environnement approprié si elles existent.
- [ ] Une procédure de retour et les vérifications après livraison existent si le projet est déployé.
- [ ] Les actions humaines restantes sont suivies comme tâches ; elles ne disparaissent pas dans une clôture.
- [ ] La publication ou le déploiement correspond à la destination et à la portée autorisées.

Après livraison, observer le parcours essentiel et conserver la preuve. En cas d'échec, appliquer la procédure de retour prévue et conserver les éléments du diagnostic.
